# Cokins - Activity-Based Cost Management: An Executive's Guide (2001) - functional capabilities

Read in full (ch. 1-11 + Appendix; index skipped). Terminology: R = resources, A = activities, FCO = final cost objects. Closed system: sum(R) = sum(A) = sum(FCO) (also the process view: sum(activities) = R=A=FCO).

| Area | Capability (one line, imperative) | Detail: inputs → calculation/formula → output | Source (chapter) | Weight (core/advanced/niche) |
|---|---|---|---|---|
| CENTERS | Import GL / fund-accounting expense balances as the "resource" layer (by cost center x account) and keep them reconciled | GL balances per period (payroll, purchasing, depreciation...) → loaded as resources; total resources must equal total costs assigned to all cost objects (foot-and-tie, no double counting) → reconciliation report; ABC translates the GL, never replaces it | Ch1, Ch2 | core |
| CENTERS | Model resources as the pool of capacity (people, equipment, facilities, supplies, utilities, capital) with expense vs capacity | Resource = period expense + capacity measures (hours, FTE, sq ft, machine-hours) → capacity exists only at resource level, never at activity level → resource master with physical capacity | Ch2, Ch8 | core |
| CENTERS | Separate wage vs non-wage resources and trace non-wage expenses to activities (top ~10 items cover ~90%) | Non-wage ledger items → resource driver (usually 1-4 target activities, sometimes dedicated to a single activity) → activity cost | Ch9 | core |
| CENTERS | Support departments serving each other (reciprocal / shared services): allow activity-to-activity cost flows, optionally reciprocal (simultaneous) solution | Giver activity cost + intermediate driver → receiver activities; alternative: iterative loop until residual is nominal; show direct vs allocated (received) cost separately for traceability → no circularity if the activity is split into finer ones | Ch2 | advanced |
| CENTERS | Separate primary expenses (incurred in the activity cost center) from secondary expenses (received via activity drivers) for responsibility accounting | Primary = resource-driver cost; secondary = cost received from other activities at the giver's driver rate → manager is accountable for primary cost + quantity consumed from secondary, not the rate | Ch2 | advanced |
| CLASS | Maintain an activity dictionary with "verb-adjective-noun" naming and a chart of activities in place of (and mapped to) the chart of accounts | Activity name + owner + process membership → activity master; user-defined wording; standard dictionaries only one summary level above base level | Ch1, Ch9, Ch10 | core |
| CLASS | Define multiple cost-object types and classify them (supplier, product/service line, order type, freight type, channel, customer, segment, geography, project, business-sustaining) | Cost-object master with type/hierarchy ("predator food chain": cost objects consuming other cost objects) → drives P&L layers and multidimensional views | Ch2, Ch3, Ch7 | core |
| CLASS | Classify activities by cost-hierarchy level (unit-level, batch-level, product/customer/supplier sustaining, business sustaining) | Tag on each activity: unit (driver varies with units), batch (varies with events/set-ups/invoices), cost-object sustaining (policy; time-based), business sustaining → decides the assignment path and layer in the P&L | Ch3, Ch2 | core |
| CLASS | Provide user-defined attributes on activities (and optionally resources/cost objects), scored/graded, with cost trailing along | Attribute (e.g. value-adding level critical/necessary/regulatory/postponable; importance; performance vs expectation; strategy-fit weight; core/sustaining/discretionary; reactive/proactive; centralized/decentralized; near-term impactability) → activity cost tagged → roll-up by attribute value into processes and cost objects (blend of "paint colors") | Ch1, Ch2, App. | core |
| CLASS | Analyze two attributes together (importance x performance quadrant matrix) with activity cost per quadrant | Two attribute scores per activity → 2x2 matrix with $ per cell and hint (scale back, improve, leverage, outsource) → bubble/heat-map report | Ch2, Ch5 | advanced |
| CLASS | Track "cost behavior" classification of resources/costs (sunk, committed, fixed, step-fixed, semi-variable, variable, discretionary) | Per-resource behavior tag + planning-horizon → used by predictive module and by marginal vs full absorption views | Ch8, App. | core |
| ALLOC | Run multistage cost assignment network: R→A (resource drivers), A→A (intermediate/activity drivers), A→FCO (activity drivers), FCO→FCO (cost-object drivers) | Cost × (driver qty to target / total driver qty); intermediate drivers reassign each activity's own cost + cumulative input cost; arbitrary depth without double counting → cost object cost; 100% conservation | Ch1, Ch2 | core |
| ALLOC | Compute activity driver rate (unit cost of activity output) | Activity cost / total period driver quantity (example: $100,000 recruiting / 100 events = $1,000/event) → rate; charge = rate × quantity used | Ch2 | core |
| ALLOC | Support the four driver types, all quantitative: resource driver, activity driver, cost-object driver (+ non-quantitative "cost driver" as root-cause label) | Driver master with type; driver quantities per target (transaction counts, time, percentages that sum to 100%); store higher-order cost driver text for root-cause analysis | Ch1 | core |
| ALLOC | Accept driver quantities as either transactional (imported) or estimated percentages, with a "ladder of driver assignment techniques" | Assignment methods in decreasing accuracy: direct trace, cause-and-effect driver, directional (headcount), even spread / prorate on cumulative costs of previous assignments; flag each assignment's quality; vital few from feeder systems, rest estimated | Ch2 | core |
| ALLOC | Assign activity costs via time-based (minutes/hours) or unit-equivalent drivers; allow switch when event durations vary widely | Event count assumes equal duration; if range of times broad → split activity (quick vs long jobs) or use time drivers → driver choice per activity | Ch2 | advanced |
| ALLOC | Two-step "grouping + fan-out" for large cost-object populations (SKU/customer) | Estimator assigns % of activity to 10-20 groups (cost-object profiles/clusters) → within group fan out to members by a volume measure → members' costs | Ch2, Ch9 | advanced |
| ALLOC | Trace business-sustaining costs to a separate "business sustaining" cost object and optionally absorb them by pro-rata on direct-traced cost | Sustaining cost object (senior management, regulators, R&D, idle capacity) kept apart; optional absorption = sustaining cost × (object's traced cost / total traced cost) → "management tax" layer, included or excluded depending on decision | Ch2, Ch6 | core |
| ALLOC | Provide audit trail / drill-back from any cost object to activities and resources | Every cost flow stored as path with driver, rate, quantity → drill-down and "bill of activities" per product/service/customer | Ch1, Ch2, Ch3 | core |
| ALLOC | Provide traceability of period-end totals: driver quantities reused from prior period when distribution not materially changed | Driver distributions normalize to 100% → update only the vital few each period → refresh without full re-collection | Ch2 | advanced |
| FC | Support marginal (variable) vs full absorption costing of the same model, decision-dependent | Include/exclude sustaining, idle capacity, sunk depreciation, R&D by decision and horizon → alternative cost views from the same network; "costs are situational" | Ch3, Ch6 | core |
| DC | Assign directly traceable costs first (project/work order, standard routing/BOM, then ABC driver, allocation only as last resort) | Preference ladder: 1 project/work-order charging (timesheet), 2 standard costing, 3 ABC activity driver, 4 allocation → per-cost-line assignment method, accuracy vs effort | Ch2, Ch6 | core |
| DIFF | Reassign overhead and distribution costs to cost objects by consumption so unit cost differs by product/order type/customer | Activity rate × driver quantity consumed → unit costs reveal subsidization; report distortion (STD-ABC)/STD per product ranked by volume (S-curve) | Ch1, Ch3 | core |
| STD | Calibrate ABC driver rates as "standard" rates on practical capacity and keep separate from actual-cost operational control | Std rate = activity (resource) cost at practical capacity / practical driver quantity (practical capacity = theoretical less planned idle/protective); strategic ABC refreshed monthly/quarterly, excluding variances and abnormal waste → stable product cost | Ch3 | advanced |
| STD | Support dual cost systems (strategic ABC vs operational control) with controlled exchange | ABC outputs budgeted rates/practical capacity to control system; control system returns variances to test std validity; permanent changes to std rates only when sustained | Ch3 | advanced |
| STD | Offer ideal / standard / actual cost definitions | Ideal = standard + allowable waste; standard = actual ± variances at practical capacity; actual = period average → chosen per use | Ch3 | niche |
| STD | Maintain a GAAP-compliant ABC database/version for COGS and inventory valuation distinct from decision-support versions | Version/scenario per purpose (GAAP vs management) with different assumptions (replacement cost depreciation, capacity treatment) → separate outputs | Ch3 | advanced |
| BUDGET | Generate activity-based budget (ABB/P) by running the model "backward" from forecast demand | Step 1: forecast cost-object volume × activity driver usage per unit → activity requirements (driver qty); Step 2: activity requirements ÷ physical resource driver rates (hours, FTE, sq ft) → resource requirements vs available (shortage/excess); Step 3: adjusted resource expenditure → pro forma ABC → budgeted activity/product/customer costs and profit (example: 105 events × $1,000 = $105,000, but cash expense only changes if capacity is changed) | Ch2, Ch8 | core |
| BUDGET | Provide "closed-loop" adjustment levers: capacity, consumption rates (productivity), demand, price, resource unit cost | Iterate until capacity balanced and financial result acceptable; each lever recalculates the network → scenario with before/after P&L | Ch8 | core |
| BUDGET | Model step-fixed and semi-variable resource behavior in the budget (resources in lumps; relevant range) | Resource capacity unit size (FTE, machine), behavior type, lead-time to adjust → required resource rounded up to step; expense changes only when capacity is acquired/retired | Ch8 | advanced |
| BUDGET | Convert ABB/P output into formal budget format (cost center x GL account) and support joint budgeting by multiple managers | Map activity/resource requirements back to cost centers/accounts/skills; show gap vs skills of existing workforce → budget in classic format plus activity view | Ch8 | advanced |
| BUDGET | Warn when forecast mix/volume leaves the calibration range (extrapolation risk) | Flags: significant mix change, volume outside relevant range, near-constraint resources, volatility, heterogeneity, resource dedication → validity indicator on forecast | Ch8 | advanced |
| VAR | Compute variance analysis for indirect/activity costs (planned vs actual spending, rate and volume variances) | Actual vs budget per resource; actual rate vs standard rate; actual driver qty vs plan; standard cost + variances = actual cost → exception report; used for control, not for product cost | Ch3, App. | advanced |
| ABC | Produce cost per unit of intermediate and final output (cost per invoice, per order, per deposit, per recruiting event), with activity composition | Activity cost / output qty and "bill of activity costs" per output → unit-cost list and trend; benchmark internally/externally | Ch1, Ch5, Ch9 | core |
| ABC | Produce product / service-line profitability with layered margins | Revenue (price × volume) - direct material - unit/batch activities → Gross Margin1; - product/brand sustaining → Margin2; ... ; sum of all products reconciles to P&L | Ch3 | core |
| ABC | Produce channel / order-type / freight-type profitability | Cost objects for channel, order type, freight type with activity drivers (shipments, visits, orders), re-traced to customers by their mix (cost-object drivers) → channel P&L | Ch3, Ch4 | core |
| ABC | Produce customer / segment P&L with margin layers and "cost-to-serve" | Customer margin: sales - supplier-related (TCO) - direct material - brand sustaining - product sustaining - unit/batch - outbound freight - order type - channel type - customer sustaining - customer unit/batch - business sustaining = operating profit; - capital charge = economic profit; each line also as % of sales; sum of customers = company P&L | Ch3, Ch5 | core |
| ABC | Cost-to-serve activities for customers (order processing, billing, A/R, customer service, post-sale, selling & marketing) with measurable drivers | Customer-specific activity drivers (orders, calls, returns, visits, deliveries) × rates → customer cost-to-serve | Ch3 | core |
| ABC | Customer profitability profile (cumulative "fishing pole / whale curve") and ranking | Customers (or products) sorted by profit descending; cumulative profit chart; last point = reported net profit; identify unrealized profit (peak minus end) and loss makers | Ch3 | core |
| ABC | Customer profitability matrix (product-mix margin vs cost-to-serve) with segments (passive, savvy, cheap, aggressive...) | X = cost-to-serve, Y = product mix margin per customer → quadrant and migration actions; scatter volume vs profit | Ch3 | advanced |
| ABC | Customer lifetime / time-value view: separate non-recurring acquisition costs from recurring; cumulative profit over periods | Periodic ABC results per customer/product over time + acquisition cost + growth/maturity phase → cumulative break-even and lifetime value (ABC itself is single-period snapshot) | Ch3 | advanced |
| ABC | Supplier cost / total cost of ownership (TCO) per supplier and per purchased item | Supplier-caused activities (PO processing, returns, inspection, expediting, disputes) incl. hidden costs in other departments + purchase price → TCO per vendor, re-traced into purchased products | Ch2, Ch4 | advanced |
| ABC | Multidimensional (OLAP-style) analysis of costs/profits by product, customer, channel, supplier, geography, salesperson, location | Dimension tags on cost objects and transactions; cross-tab and drill → views over same data | Ch3, Ch7 | core |
| ABC | Local (child) models consolidated into an enterprise (parent) model | Child ABC models (department/process/division) with own activities and rates; consolidation maps outputs to parent's activities/cost objects; costs unchanged by consolidation; representative-branch models scaled by branch count | Ch2, Ch9 | advanced |
| ABC | Represent final-final cost object logic (customers consume cost objects in a chain) via cost-object drivers | Customer purchase quantities (sales register) × unit costs of products/order types → customer cost without double counting | Ch2, Ch3 | core |
| ABC | Quick-start / rapid prototyping workflow supporting iterative model refinement (Model 0, 1, 2) | Org chart + headcounts → 3 main activities per group (>90% of time, 5% increments, average salary) → driver choice and estimated %, cost-object profiles (2×2×2 customer clusters), 10 non-wage items; recalc; versions of models compared; refine only where sensitive | Ch9 | core |
| ABC | Provide sensitivity / error analysis to find which estimated driver quantities matter | Vary driver quantities (+/- x%) and show impact on cost-object cost; rank candidates to upgrade to transaction data ("is the climb worth the view") | Ch2, Ch9 | advanced |
| ABC | Import/export automation: scripted loading from GL, payroll, ERP, data warehouse; export unit rates and costs to quoting, CRM, scorecard, OLAP | ETL of financial + operational (driver) + empirical (estimates) data per period; outputs published for other systems | Ch1, Ch4, Ch7, Ch11 | core |
| TDABC | Estimate activity time per unit/transaction (time-equation style) when event durations differ | Cokins uses time drivers (minutes) or splits activity by duration class rather than a time equation; rate = cost per minute of resource or activity | Ch2, Ch6 | advanced |
| TDABC | Derive resource-driver percentages from employee time estimates (time sheets or "vital few" estimating for all) | % time per activity per group, 5% steps; salary × % → activity cost; optional average salary in first model | Ch2, Ch9 | core |
| ABM | Roll activity costs into business processes (horizontal view) and provide sum-over-process cost, equal to vertical total | Activities tagged to process/sub-process; process cost = sum of its activity costs (sequence additive); reconcile with vertical view | Ch1, Ch2 | core |
| ABM | Provide activity analysis (need, efficiency, value) and cost-driver root-cause analysis; link activity cost to driver and "driver of driver" | Per activity: required? efficient? value-adding? → reduce frequency / eliminate low-value work; store higher-order cost-driver notes | Ch2, Ch1 | advanced |
| ABM | Provide benchmarking (internal/external) on unit cost of outputs and work elements | Comparable codified activity/output definitions across units/companies → unit-cost comparison to find best practice | Ch5, Ch6, App. | advanced |
| ABM | Customer-preference alignment: revenue equivalents and value multipliers per segment and trait | Revenue equivalent(seg, trait) = segment sales × trait preference weight (weights sum 100%); value-added-core activity cost scored (by supplier) to traits; value multiplier = revenue equivalent / value-added core cost; <2 overspending, 2-6 maintains, >6 check customer satisfaction (advantage vs risk) | Ch4 | niche |
| ABM | Test price/service-level trade-offs for demand shaping | Incremental change in revenue must be < incremental cost saving for service reductions (and > cost increase for upgrades); costs derived from activity changes → accept/reject per option | Ch4 | advanced |
| ABM | Support "seven actions" what-if for profit improvement (new product, raise price, manage demands, drop, fix/focus process, offer options) with effect on profile curve | Scenario edits in volume/price/driver quantities; idle capacity effect shown (savings only if capacity removed or reused) → before/after profit profile | Ch3 | advanced |
| ABM | Support outsourcing / make-or-buy / drop-product analysis showing remaining vs removable costs | Activity-based identification of costs that go away, remain (idle capacity), or are added → net savings | Ch6 | advanced |
| CAPACITY | Measure unused capacity by resource with time-status modes (productive, nonproductive, idle) per CAM-I model | Theoretical capacity (24x365) split into productive; nonproductive (standby, waste, maintenance, changeover, testing, training); idle (off-limits, non-marketable, marketable without demand) → time and $ per mode | Ch6 | core |
| CAPACITY | Compute cost of unused/idle capacity and assign it to a responsible object, not to products | Unused cost = resource expense × (1 - used capacity / practical capacity) (cost of resources supplied minus cost used); assign to business-sustaining / sales / management cost object → product cost excludes it | Ch6, Ch8 | core |
| CAPACITY | Expand equipment resource into activities per time-status mode with own driver assignments | Equipment activities (make good product, changeover, maintenance, testing, waste, idle); changeover by number of set-ups, maintenance to products using machine, waste to failed products or management → many cost paths | Ch6 | advanced |
| CAPACITY | Allow depreciation on replacement cost basis and per activity mode | Replacement cost of assets × rate normalized so total equals book depreciation; options to exclude sunk depreciation from marginal view | Ch6 | advanced |
| CAPACITY | Report operations vs sales responsibility metrics (reduce nonproductive, fill/remove idle) | Nonproductive $ owned by operations; idle $ owned by sales/business; reduction of nonproductive increases idle (good) → complementary KPIs | Ch6 | advanced |
| CAPACITY | Record real-time/static capacity status by interval (week/day) and integrate dynamic scheduling/simulation for short horizons | Time-status per resource per interval from MES/ERP; ABC for static costing; simulation/APS for dynamic capacity | Ch6, Ch8 | niche |
| JOINT | Charge back shared services by consumption (full-absorption chargeback, SLA, price quote) | Service activities → service cost objects (base services, special services) → billed to internal customers by volume x unit rate; governance/policy costs separated to executive management; SLA with price/volume/response | Ch6 | advanced |
| JOINT | Support transfer cost (not cost-plus) between divisions and reconcile with external profit only | ABC cost of transferred item incl. only its traced costs; margin only at external exchange | Ch3, Ch6 | niche |
| TARGET | Support target costing: target cost = market price - target margin, with ABC rates for feature-based cost estimates | Target price, margin → allowable cost; feature-based cost = sum(feature driver quantity × activity rate), e.g. holes punched × rate | Ch3 | advanced |
| LCC | Track non-recurring (development, acquisition) cost separately and life-cycle profit per product/customer across periods | Nonrecurring cost buckets + periodic ABC results → cumulative lifetime profit per object | Ch3 | niche |
| COQ | Classify 100% of activity costs into error-free vs cost of quality categories (prevention, appraisal, internal failure, external failure) with sub-categories | Attribute on every activity with indented sub-classes; total COQ + error-free = total expenditure (reconciles to ledger); roll-up by process/product/customer | Ch2, Ch6 | core |
| COQ | Report COQ trend and shift (reduce failure, adjust prevention) | COQ by category per period; initial typical split failure 65-70%, appraisal 20-25%, prevention ~5%; cost per unit driver trend | Ch6 | advanced |
| PROJ | Blend project / job-order costing with ABC (indirect/support costs flow to project worksteps, projects, customers, or sustaining) | Project hierarchy (legal entity - project - work order - phase - task); direct labor/equipment by timecard; ABC activity driver rates charge overhead to tasks (path 1), project (2), customer (3), sustaining (4), plus further reassignment (5) | Ch6 | advanced |
| PROJ | Compare plan vs actual per project (spending, schedule) and show completion | Project accounting keeps budget/plan, % complete, variances (ABC alone does not) | Ch6 | advanced |
| KPI | Feed balanced / weighted scorecard with ABC measures (unit costs, process costs, COQ, profitability, capacity) and cascade by level | Measures per perspective (financial, customer, internal process, learning); weights per level summing to 100%; leading vs lagging; unit costs belong in non-financial perspectives; ability to replace measure/rebalance weights when strategy changes | Ch5 | advanced |
| KPI | Attach strategy-alignment attribute to activities and produce heat maps of cost vs strategic fit | Strategy weighting score per activity → cost per score band → heat map/bubble diagram | Ch5, Ch2 | niche |
| FIN | Impute capital charge (cost of capital) to activities, products and customers to give economic profit | Capital charge = average balance × cost of capital rate: inventory → products; receivables → customers; payables credit → suppliers/products; net fixed assets → equipment activities; economic profit = operating profit - capital charge (EVA/SVA); rate is an input parameter | Ch5 | advanced |
| FIN | Provide VBM value-driver tree (EBIT, NOPAT, capital charge, SVA) linked to customer/product views | NOPAT = EBIT - adjusted taxes; SVA = NOPAT - WACC × net assets | Ch5 | niche |
| FCST | Quote customer orders with rule-based activity costing and profit-margin acceptance test | Order lines/options → driver quantities × activity rates (+ capital charge) → cost; compare to quoted price; threshold margin; decision-dependent inclusion of sustaining/idle costs; at web speed from an ERP/web quote | Ch4, Ch8 | advanced |
| FCST | Run what-if scenarios on volume/mix/prices/capacity and compare against baseline | Scenario copies of the model with changed drivers, capacity, price; net-change (delta OE) comparison; pro forma P&L by product/customer | Ch8 | core |
| FCST | Compute differential profitability (delta T - delta OE) test per decision | Change in throughput (sales - totally variable cost) minus change in operating expense > 0; OE change taken from ABC resource model | Ch8 | niche |
| FCST | Optional TOC throughput view: throughput per constraint unit ranking for short-run product mix | T/CU = (price - material) / constraint minutes per unit; profit = throughput - operating expense | Ch8 | niche |
| FCST | Link to discrete-event simulation via base-period synchronization and resource expenditure calculator | Simulator outputs resource needs/driver quantities → expense calculator (variable, semi-variable, step-fixed, fixed) → ABC pro forma | Ch8 | niche |
| OTHER | Provide price/margin integrity checks (cost-plus vs market) and sales-incentive measure on margin, not revenue | Report salesperson/customer commission basis vs contribution margin | Ch3 | niche |
| OTHER | Maintain audit and version control of models (period, scenario, GAAP vs decision, iteration) with documented assumptions | Model versions (Model 0,1,2, production), assumptions register for each decision-dependent treatment | Ch2, Ch3, Ch9 | advanced |
| OTHER | Provide supply-chain / inter-firm cost transparency (open-book: each partner computes cost and margin per product-channel-customer intersection) | Partner ABC outputs exchanged per product/channel/customer; separates cost from profit; costs shared via standard (SCOR) activity framework | Ch4 | niche |
| OTHER | Support multi-entity (division + HQ) models where HQ activities are traced to divisions by usage | HQ activities with drivers to divisions; other divisions modeled with single activity | Ch9 | niche |
