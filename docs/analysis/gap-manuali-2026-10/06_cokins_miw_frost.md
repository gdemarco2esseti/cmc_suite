# ABC/ABM functional capabilities — Cokins "ABC Management: Making It Work" (Cokins MIW, 1996) + Frost "ABCs of Activity Based Management" (Frost, 2005)

Sources abbreviated: Cokins MIW ch.N = Gary Cokins, Activity-Based Cost Management: Making It Work; Frost = William Frost, ABCs of ABM (chapter = "Step N").

| Area | Capability (one line, imperative) | Detail: inputs -> calculation/formula -> output | Source (book + chapter) | Weight |
|---|---|---|---|---|
| ABC | Maintain an activity dictionary with verb-adjective-noun names and an indented hierarchical code (process > activity > task). | Input: activity name, code, owner, function and process code. Same activity carries two codes (by function and by process) so costs roll up either way ("string the pearls"). Lowest-level code holds the data; every higher level is a formula roll-up. Tasks may be described but not costed. Output: dictionary + roll-up tree. | Cokins MIW ch.4 (4-5), ch.7 (7-5); Frost Step 3-5 (Sub-Drivers) | core |
| ABC | Define resources and resource cost pools sourced from the general ledger (labour, fringe, superfringe, depreciation, purchased services, materials). | Input: GL account balances per period, headcount/salary by natural work group. Output: resource cost list that must total 100% of the P&L expenses in scope; category split: materials (traced direct) vs activity costs (people + equipment). | Cokins MIW ch.4 (4-4), ch.7 (7-6, 7-9); Frost Step 6 | core |
| ABC | Assign resource costs to activities via first-stage resource drivers (time-effort %, direct charge, measured usage, estimate). | Input: % time per natural work group per activity (rounded to 5%), average salary+fringe per group, FTE. Activity cost = sum(resource cost x driver %) with each resource assigned 100%. Output: costed activities; reconciles to GL/P&L. Direct charge preferred, estimate second, arbitrary allocation last resort. | Cokins MIW ch.4 (4-1), ch.7 (7-6, 7-7) | core |
| ABC | Support multi-stage cost flow: activity-to-activity (intermediate drivers) and activity-to-cost-object (final drivers), including stage-skipping paths. | Network of nodes (resources, activities, intermediate objects, final objects) with assignment paths and driver quantities. Each sending node distributes 100% of its accumulated cost pro-rata to receiving nodes' driver consumption. Conservation theorem: total in = total out, no cost created/destroyed or double counted. Output: cumulative and incremental cost per node + audit trail back to resources. | Cokins MIW ch.4 (4-1, Figs 4-4..4-14) | core |
| ABC | Compute activity cost driver rates and trace activity costs to cost objects. | Rate = total activity cost / quantity of driver units in period; cost to object = rate x object's driver units consumed. Driver data: quantity per cost object (e.g. invoices per customer) from feeder systems or estimated. Output: unit cost of each activity output and cost per object. | Cokins MIW ch.4 (Fig 4-3), ch.7 (7-10); Frost Step 5-6 | core |
| ABC | Manage the activity cost driver catalogue with selection guidelines and a driver-precision ladder. | Attributes: name, unit, definition, data source, quantifiability, correlation to consumption, cost to measure; guidelines: avoid drivers for immaterial activities, few unique drivers, drivers that encourage improvement, economical to measure. Ladder from simple (manual % estimate to next object) to transaction-volume drivers from feeder systems, phased in over time. | Cokins MIW ch.7 (7-10, Figs 7-17..7-19); Frost Step 3 (Appx A) | core |
| ABC | Define final cost objects in a multi-dimensional hierarchy (product, service, customer, channel, order, product-customer-order). | Granularity of cost objects is a model choice (activity detail vs object granularity are separate axes). Lowest cost object = product-customer-order combination. Output: cost per object at any hierarchy level. | Cokins MIW ch.3 (3-4), ch.4 (4-1); Frost Step 3 (Products + Cost Drivers) | core |
| ABC | Trace customer-driven and supplier-driven costs to customers/suppliers, not only to products. | Customer-related drivers (orders, order changes, sales calls, complaints, trucks shipped, special handling) and supplier-related activity costs (packaging complications, receiving effort) assigned to customer/supplier objects; landed cost of a purchased part = invoice + supplier-behaviour activity cost. | Cokins MIW ch.3 (3-4, 3-5), ch.7 (Fig 7-18) | advanced |
| ALLOC | Provide direct-trace-first costing; allow allocation only as flagged last resort and never to balance a variance. | Rule: prefer direct charge, then driver-based tracing; arbitrary allocations (sq ft, headcount) must be explicit and visible. The difference between actual expense and ABC cost is reported as variance and is NOT allocated out. | Cokins MIW ch.1 (1-3B), ch.4 (4-2), ch.7 (7-6); Frost Step 7 | core |
| ALLOC | Report facility/enterprise-sustaining costs separately as a surcharge ("enterprise tax"), not baked into process or product cost. | Costs not caused by products/customers (rent, taxes, lawn care, HQ) go to sustaining activities; shown as an isolated, visible surcharge only when full absorption is required (GAAP inventory, pricing). | Cokins MIW ch.3 (3-4), ch.7 (7-9) | core |
| ALLOC | Classify purchased (non-wage) GL expenses into three paths: direct to activity, enterprise-sustaining, employee use and occupancy (superfringe). | Input: Pareto of ~90% of non-wage GL accounts. Superfringe (phones, laptops, furniture, travel) folded into per-employee labour cost; remainder small accounts also baked into superfringe. Output: resource costs ready for activity assignment. | Cokins MIW ch.7 (7-9, Figs 7-12, 7-13) | advanced |
| ALLOC | Cost shared resources by consumption (space by sq ft, machines by hours, storage by MB, shared tech by usage) instead of flat departmental split. | Resource cost per unit of capacity (annual cost / annual capacity) x units used; sq-ft measurement per department; dedicated space can be a separate occupancy line. | Frost Step 6 (Resource Costing), Step 8 (Occupancy) | advanced |
| CENTERS | Hold a department / cost-centre / business-unit hierarchy with roll-up of actuals, ABC cost and variance. | Departments linked to organisation chart; actual expense and ABC cost rolled up to Business Unit; drill-down from BU to department to expense line; no "summary departments" (they destroy traceability); product/portfolio view uses a different hierarchy over the same data. | Frost Step 7, Step 8 (Summary Depts, BU roll-up); Cokins MIW ch.1 (1-3A) | core |
| DC | Classify each resource cost line as fixed or variable (two classes only; no semi-variable) with documented rules. | Per resource line a Fixed/Variable flag. Rule of thumb for non-exempt labour: variable only if hours flex with volume (sent home, loaned); fixed if full shift regardless and idle capacity reporting wanted. Exempt labour and benefits fixed; vendor per-transaction fees variable; fixed costs step-change with capacity. | Frost Step 6 (Fixed and Variable Costs, Appx B); Cokins MIW ch.1 (1-3D) | core |
| DC | Split every ABC unit cost into fixed and variable components and price from variable cost. | Fixed ABC cost = fixed rate x activity time; variable ABC cost likewise; total = sum. Variable pricing: floor price = variable ABC cost when existing business already covers fixed costs (check via Product Profitability report) and capacity exists. | Frost Step 6 (Variable Pricing), Step 8 (Break-even) | advanced |
| FC | Compute full (total service) cost = ABC cost + idle-capacity burden + SG&A burden for profitability and pricing, keeping the three components visible. | Total cost = ABC + idle capacity (15% x ABC in example) + SG&A (computed on raw ABC, not on the adjusted cost). Example: $90 ABC + $13.50 + $13.50 = $117. Operations managed on ABC cost; profitability uses total service cost. | Frost Step 6 (Idle Capacity, SG&A), Step 7; Cokins MIW ch.3 (3-4), ch.7 (7-9) | core |
| FC | Contrast average, full-absorption, life-cycle and activity-based cost views and warn about the volume-driven death spiral. | Average cost = total expense / volume (moves with volume); full absorption includes idle capacity and can price the firm out of market (price up -> volume down -> unit cost up). System should support a fixed-rate idle burden rather than a volume-recomputed one. | Frost Background (Costing methods); Cokins MIW ch.1 (1-3D) | niche |
| ABC | Calculate ABC cost per cost driver by Resource Costing: sum over resources of (cost per unit of resource capacity x resource units used per item). | Table per department: expense line, fixed/variable, annual expense, capacity measure (total labour hours 12,480; machine hours 37,440; sq ft; MB), cost per unit of resource = expense / capacity; resources required per item (from activity time); contribution per item. Example $0.2784 total vs hourly-rate $0.2887. Output: ABC cost per driver by resource line, fixed vs variable. | Frost Step 6 | core |
| ABC | Offer the Hourly Rate method as the simpler alternative (department expense / working hours x activity time) with fixed and variable hourly rates. | Hourly rate = dept expense / (employees x hrs/wk x wks) e.g. 180,150/12,480 = $14.44; ABC cost = rate x hours per item. Variant: operating hours net of vacation, holidays, sick days (2,080 - 184 = 1,896). Limitation: no per-resource capacity insight. | Frost Step 6 | advanced |
| ABC | Support departments with mixed salaried/hourly staff, vendor-per-item costs, call-centre telecom, mail operations and IT resources. | Separate resource lines for salaried vs hourly labour (avoid double counting); vendor cost lines (e.g. $15 credit report x 1 per item); telecom fixed (lines) vs variable (minutes); IT storage/server/time capacity measures; R&D/new-systems development tracked as projects, not in ABC. | Frost Step 6 | advanced |
| TDABC | Capture activity time per transaction type and position title via time studies (stopwatch, MTM, bar-code, video, PDA, system logs) as the core costing input. | Per department: Sub-Driver/activity, seconds and decimal hours per item, position title (to spot queues and hand-offs), roll-up to Cost Driver; time the activities covering ~80-85% of effort, rest as "other"; time on busy days; sample size from variance, confidence and error margin; manager sign-off. Cost driver time = sum of department times. | Frost Step 5 | core |
| TDABC | Estimate labour conversion cost by cycle time (demand-pull): cost per output = cycle-time x cost-load rate per productive hour. | Cost-load rate = payroll / (employees x paid hours net of breaks) e.g. $60,000 / 2,560 h = $23.4375/h; cost per reservation = 7.5 min x rate = $2.93. Mismatch between standard cycle times x actual volume and payroll is shown, optionally rate rescaled to reconcile. Enables capacity planning and constraint checks; the % method cannot. | Cokins MIW ch.7 (7-8, 4-3) | core |
| TDABC | Warn/prevent use of survey % or tick-sheet averages (total hours / volume) for ongoing costing because they assume 100% utilisation and are volume-sensitive. | Activity time = % of time x hours / volume; falls as volume rises and vice versa without any process change; hides idle capacity. Surveys allowed only for initial benchmark ABC cost; ongoing costing needs standard times. | Frost Step 5 | advanced |
| TDABC | Compute staff estimates (FTE) from activity times and projected volumes. | FTE = sum over drivers (hours per item x projected volume) / annual hours per FTE, rounded up; add allowance for idle/vacation; alternative productivity ratios for SG&A (revenue per FTE, accounts per FTE) to size staffing for growth scenarios. | Frost Step 8 (Staff Estimates) | core |
| CAPACITY | Segment capacity into used, idle, unused (reserve) and excess/nonproductive and cost each per resource and department. | Theoretical capacity (24x7) -> idle (policy, no demand) / nonproductive (setup, rework, repair, training) / productive. Frost: used, idle, unused (reserve, revert to excess after 2 quarters), excess. Unused-capacity cost is isolated into an "unused capacity activity" and NOT charged to products. | Cokins MIW ch.1 (1-3D), ch.5 (5-3); Frost Step 6 (Idle Capacity FAQ) | core |
| CAPACITY | Calculate idle capacity cost, percent and rate per resource and period. | Idle $ = actual expense - total ABC cost (volume x ABC cost); idle % = idle$/actual expense (15%); idle capacity rate (burden) = idle$ / ABC cost (17.6%) = 1/(1-idle%) - 1; adjusted ABC cost = ABC x (1+rate). Corporate or BU-level rate updated 1-2x per year, not monthly; default 15% when no history; shown by labour/machine/occupancy. | Frost Step 6, Step 8 (Labor Capacity) | core |
| CAPACITY | Model step-fixed resources (machine added when capacity exceeded) and the capacity vs demand graph. | Capacity = units x capacity per unit (2 x 2,000); fixed cost steps when demand exceeds capacity; idle quantity = capacity - volume (6,000 - 5,000); used to decide whether new volume needs more fixed cost. | Frost Step 6 (Fixed and Variable Costs) | advanced |
| CAPACITY | Show impact of an activity-time reduction: cost moves from ABC bucket to idle bucket unless volume grows or resources are redeployed. | Before/after table: hours available, hours per item, volume, used hours, idle hours, ABC cost, idle cost; savings only recognised when headcount/expense actually falls or volume/revenue rises. | Frost Step 8 (Increasing capacity) | advanced |
| CAPACITY | Report idle capacity trends and actions (loan out and charge time to other dept, attrition, sublease, share shifts) with acceptability band (10-15%). | Idle cost by labour/machine/occupancy vs time, capacity utilisation %, 3-4 month trend rule; loaned-employee hours charged to the receiving department; facility layout/sq ft inventory. | Frost Step 8 (Labor/Occupancy Capacity) | advanced |
| CAPACITY | Provide bottleneck (Theory of Constraints) analysis of process step capacities and throughput. | Step capacity (items/h) per step; process throughput = min(step capacities); queue growth rate = upstream rate - bottleneck rate; chart capacity vs actual throughput. Cokins: TOC/throughput accounting (T, I, OE) complements ABC; ABC costs stay stable while TOC loaded costs wander with the bottleneck. | Frost Step 8 (Bottleneck Analysis); Cokins MIW ch.5 (5-2) | advanced |
| VAR | Produce the ABC variance report: actual expense (GL) vs ABC cost (volume x ABC cost) by department and by resource line. | Variance = actual - ABC cost per line; e.g. labour +25% (idle labour), repairs -7%; multiple periods side by side; used to spot idle capacity, stale ABC costs or process change; fix at source, not allocated. | Frost Step 6-7; Appx F | core |
| VAR | Provide an organisational / business-unit ABC variance roll-up with drill-down to department and expense line. | BU report = sum of department variances; contribution of each department (e.g. Dept B = 70% of variance); drill from BU to department to resource line. | Frost Step 7, Step 8 | core |
| VAR | Provide a variance-cause diagnostic checklist (symptom -> likely causes) per expense category. | Rule table: actual > ABC labour => idle labour, volume decreased, loaned staff still charged; actual < ABC => process improvement or volume up; depreciation/occupancy variances from new equipment, life change, method change, allocation change. | Frost Appx F | niche |
| STD | Treat ABC unit costs as updatable standards and keep them current without a full restudy. | Update only the changed expense category or time (e.g. repairs), cost "aging" report with last-update date; model modularity: refresh only where headcount/work mix, cost-object mix, or activity set has changed; reuse unchanged prior-period data. | Frost Step 6-7 (ABC Aging report); Cokins MIW ch.9 (9-2) | core |
| STD | Offer actual-vs-standard trend analysis (frequent actuals, rolling trend lines) rather than only deviation from stale standards. | Actual = standard +/- variance; recompute cost-driver rates each period and chart trends; ABC model as expanded standard cost with matched cost pool and driver. | Cokins MIW ch.1 (1-3F) | niche |
| BUDGET | Build activity-based budgets: planned driver volumes x ABC cost per resource + planned idle % + SG&A = budget by GL line. | Input: planned volume per cost driver (default = last year or +x%; focus on top 60-80% cost drivers, largest volumes, planned launches), ABC cost by resource line. Output: budgeted expense by GL line / department / resource, compared with current resources (hire/attrite decision). Cokins: ABC budgets regenerated from driver quantities x pre-computed rates. | Frost Step 8 (ABB/P); Cokins MIW ch.1 (1-3E) | core |
| BUDGET | Use ABB as a validation of the traditional budget and run it as rolling forecast. | Compare ABB result with traditionally planned expenses by line; re-run monthly/quarterly over rolling 12-18 months; volumes planned by Product Managers/Sales, not operations; SG&A budgeted traditionally or via internal demand survey. | Frost Step 8 (ABB/P) | advanced |
| BUDGET | Monitor actuals against ABB/P alongside ABC cost and actual expense. | Three-way report: actual, ABC cost, ABB plan per department/resource/period. | Frost Step 8 | core |
| FCST | Run what-if scenarios by changing driver quantities or activity times on the calibrated ABC model to forecast cost. | Predicted cost = forecast driver quantities x stable driver rates over relevant range; order quotation, make-vs-buy, investment justification, change-impact projection (apply planned changes to work flow and content, re-cost). | Cokins MIW ch.3 (3-3), ch.4 (4-3, Fig 4-17), ch.6 (Step 8) | core |
| FCST | Estimate cost for new products/services from standard activity times (incl. MTM/estimated motions) and add new cost drivers on demand. | New Cost Driver with estimated time per item -> ABC cost; pro-forma profitability for launches; new processes designed efficient from the start. | Frost Step 5 (MTM), Step 8 (ABB/P) | advanced |
| FIN | Reconcile resource, activity and cost-object totals to the GL / P&L and interface the GL as the cost source. | Closed system: total resource cost = total process cost = total cost-object cost; GL expense balances loaded by automated link per period; check against P&L; ABC is an off-line translator that complements, not replaces, the GL (no second set of books). | Cokins MIW ch.1, ch.3 (3-1), ch.7 (Fig 7-13), ch.8 (8-4), ch.9 | core |
| FIN | Produce transaction-level profitability as the base table, summarised by customer/household, product, portfolio and business unit. | Row = account/transaction x cost driver: revenue, total cost (ABC + idle + SG&A), profit $ and %, volume. Revenue components (fees, interest, service charges). Summaries: customer, product, portfolio (sales exec), BU; each reconciles to base. | Frost Step 7; Cokins MIW ch.1 (1-3B) | core |
| FIN | Provide customer, product, portfolio and profit-matrix (customer x service) reports with profit ranking and high-profile highlighting. | Profit = revenue - total service cost; sorted profit curve (ABC margin by product/customer, big winners and losers); matrix of customer-service profit with flag for key customers to decide re-price/eliminate/migrate channel/outsource. | Frost Step 7; Cokins MIW ch.1 (Figs 1-13, 1-14) | core |
| FIN | Compute break-even volume (with optional target margin) from fixed cost, price and variable ABC cost. | Q = FC / (SP - VC); with target margin PM: Q = FC / (SP - VC - PM x SP). Example: FC 100,000, SP 10, VC 6, PM 15% => 40,000. FC = fixed ABC cost x volume (+ idle %), same period basis. | Frost Step 8 | core |
| FIN | Support pricing and quote tools from ABC (cost-to-serve, order quotation, channel cost comparison). | Cost per cost-driver by sales channel (branch, ATM, internet, call centre) to steer customers to cheapest channel; unbundled cost-to-serve and menu pricing; order quotation using driver rates. | Frost Step 3 (driver rules); Cokins MIW ch.3 (3-5), ch.4 (Fig 4-17) | advanced |
| FIN | Calculate ROE/ROA-based savings targets by reverse-engineering financial metrics. | Goal expenses = Revenues - Goal ROE x Equity; required saving = current - goal expenses (e.g. $80,000 = 8.9%; $6,666/month); express as % per area; track actual savings (3-month average before/after, again at +1 year). | Frost Step 1, Step 8 (Verify results) | niche |
| ABM | Process view: model business processes as sequences/networks of activities with inputs, outputs, owner, customer and accumulate costs end-to-end. | Process = set of activities (any level of detail) tagged to process codes; process cost additive; enterprise relationship map -> core processes (few, cross-functional). Output: cost per process, process cost per output. | Cokins MIW ch.3 (3-1, 3-4), ch.7 (7-3..7-5) | core |
| ABM | Draw cost build-up ("mountain") graphs of cumulative process cost vs cumulative cycle time, and 3D cost topography for non-serial work. | X = cumulative cycle time (from process flow), Y = cumulative activity cost; slope as attention director; average slope = cost per FTE; before/after improvement lines; layering by value-added score. | Cokins MIW ch.7 (7-11) | advanced |
| ABM | Score activities with user-defined attributes attached at lowest activity level that flow through any roll-up. | Attributes: value-added (value-creating from customer view / value-enabling / non-value-added; degrees high-med-low-none), impactability (near and long term, or % to quantify savings), effectiveness (exceeds/meets/below), importance to strategy (critical/essential/necessary/postponable), quality content (COQ category), cost-influencing link (upstream cause -> downstream activity), cost-driver type (influence vs response). Blind scoring by separate team. Output: cost by attribute value for any process/function/object. | Cokins MIW ch.4 (4-6); Frost Step 8 (Value Added Analysis) | core |
| ABM | Combine scores into quadrant/bubble charts (effectiveness x strategic support, bubble size = cost) mapping to actions (noncritical, risk, opportunity, leverage). | Two scores define four quadrants, cost drives bubble size, third score as shading; recommended actions (persuade, scale back, outsource, invest, sustain). | Cokins MIW ch.4 (Figs 4-22..4-28) | advanced |
| ABM | Run value-added analysis (Value Added / Business Requirement / Non-Value-Added) per function in a process and quantify NVA cost and time. | Per step: value-added flag + reason; costs of NVA steps from ABC; challenge steps to eliminate or automate. | Frost Step 8; Cokins MIW ch.4, ch.7 (Fig 7-25) | core |
| ABM | Support root-cause analysis and worker fragmentation analysis on activity cost data. | Link activity cost to cost-driver magnitudes (fishbone, cause diagrams); fragmentation = distribution of an activity's hours across employees (too concentrated or too dispersed). | Cokins MIW ch.7 (7-12, 7-13) | advanced |
| ABM | Provide multi-view analysis (process, function, product, customer, region, channel, period) with OLAP-style drill, slice, rank and trend. | Same cost/driver cube viewed across hierarchies with ad hoc calculation; attributes preserved in roll-ups; multi-period reporting and benefit realisation tracking. | Cokins MIW ch.9 (9-3), ch.8 (8-5) | core |
| ABM | Provide process/activity cost drill-down from product profitability to activity breakdown ("ABC Cost Breakdown") and identify big hitters and hand-offs. | Per cost driver: sub-drivers (steps) with cost, department, position; sorted cost ranking; transport/hand-off steps; idle and SG&A lines. | Frost Step 3 (Table 3.1), Step 7 | core |
| LCC | Map the product/service life cycle flow (open > support > close; transaction flows) and link each box to departments and cost drivers. | Life-cycle flow chart per product with departments per step; high-level then detailed; used to select study areas and prioritise departments by expense; annotate expenses cautiously (shared departments). Not used as the costing engine. | Frost Background, Step 4 | advanced |
| KPI | Track performance measurement indicators incl. non-cost measures (cycle time, quality, service) alongside cost; yardstick measures of ABC project success. | Process outputs measured in quality, flexibility, delivery, cycle time, cost; project success indicators (usage frequency, requests, second pilot, decisions using the data). | Cokins MIW ch.1 (1-4), ch.3 (3-4), ch.6 (6-4) | advanced |
| KPI | Set up productivity ratios and ABM team metrics (cost per cost driver trends, savings vs team cost, idle %, ABC aging). | Cost per driver trend, savings per period vs improvement targets, team ROI (>3x salaries), ABC Aging report (last update vs variance), productivity ratios per FTE for SG&A. | Frost Step 2, Step 7, Step 8 | niche |
| COQ | Classify activities into prevention, appraisal, internal failure, external failure and report cost of quality. | Quality-content attribute on activity; cost of conformance vs non-conformance totals by process/product. | Cokins MIW ch.4 (4-6, Fig 4-21) | advanced |
| TARGET | Support target costing: allowable cost = market price - target profit, with ABC cost parameters to simulate design feature/process trade-offs. | Target cost = Market price - Target profit (vs Actual cost + Planned profit = Price). ABC supplies driver rates for design alternatives (feature-based costing, QFD, concurrent engineering); costs committed in design phase. | Cokins MIW ch.1 (1-3C), ch.3 (3-4) | advanced |
| PROJ | Track improvement initiatives and benefits realisation (before/after costs per department, product, customer). | Project list prioritised by cost size, productivity trend, complaints; savings measured as 3-month average pre vs post then 1-year; actual savings (headcount/expense reduced) vs identified; confirm no shift to idle capacity or SG&A. | Frost Step 8, Step 9 (Verifying results); Cokins MIW ch.6 | advanced |
| OTHER | Model SG&A / overhead departments with a separate SG&A burden rate (optionally by category HR, Finance, IT, BU). | SG&A rate = SG&A cost / total corporate cost, applied on raw ABC cost; breakdown report by overhead area with pie chart; SG&A managed by budget/benchmark not ABC, no idle capacity concept for Sales. | Frost Step 6 (SG&A), Step 7 | advanced |
| OTHER | Provide data import/export, feeder-system volume mapping (transaction code -> cost driver) and data-source registry. | Cost Driver table: driver, unit, definition, data source; extract of transaction codes mapped to drivers via data dictionary; automated recurring volume loads; validation vs actual transactions; online input forms with reminders, escalation to supervisor, default data. | Frost Step 3, Appx A; Cokins MIW ch.9 (9-2), ch.8 (8-5) | core |
| OTHER | Support multiple models, model consolidation, concurrent editing, large model size, scenario/version management and audit trail. | Multiple ABC models consolidated; attributes flow through consolidation; versions per time slice; documented assumptions to allow re-runs; staged models (one-time diagnostic -> repeatable -> integrated production). | Cokins MIW ch.6 (6-3), ch.8 (8-5), ch.9 (9-1, 9-2) | advanced |
| OTHER | Select ABC software with a must-have / nice-to-have scoring matrix. | Feature list weighted; vendors scored, "must have" gate, price tiebreak; open data source, extract capability. | Frost Appx E | niche |
